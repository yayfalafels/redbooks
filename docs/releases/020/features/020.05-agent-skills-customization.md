## 020.05 (open) agent skills customization

The first pass on the Claude Code agents and skills in `.claude/`. It turns the agent roster and the skill set inherited from easyMCF into a RedBooks team with generic skills, and it carries every easyMCF lesson into those skills in RedBooks stack terms. This milestone produces instruction files and an inventory, and no application code. Its work is review, extraction and rewriting, so the tracker replaces the test strategy and test cases sections of a feature build with a source inventory, a disposition of the current agents and skills, a lessons extraction, and closure checks.

## Scope

Rewrite the agents and skills in `.claude/` for RedBooks `0.2.0`, and move the lessons learned on easyMCF into generic skills. The result is an agent team that follows the RedBooks stack of FastAPI, PostgreSQL and React from the first design document onward, and carries easyMCF's lessons with no dependency on the **easymcf repo**. The bespoke `redbooks-` skills wait for the **agent skills implement customization** milestone, once the design is closed.

In scope:

01. **agents.** Every agent in `.claude/agents/` describes a RedBooks role and names the generic skills it loads. Agents with no RedBooks role are removed, and roles the release needs are added. The roster is decided in the design.
02. **process skills.** `documentation-style`, `markdown-tables`, `design-audit` and `feature-implementation-guide` carry over, with every easyMCF name, path, example and convention replaced by generic wording.
03. **domain skill.** A new `accounting` skill covers general ledgers, account types, opening balances, transfers, income statements, balance sheets, multi-currency accounts and forex gains and losses.
04. **language skill.** A new `python` skill covers project layout, virtual environments, typing, exact decimal arithmetic, logging and error handling.
05. **backend skills.** A new `fastapi` skill covers routes, dependencies, validation and OAuth. A new `postgresql` skill covers schema design, migrations, NUMERIC types and query practice.
06. **frontend skill.** A new `react` skill covers components, state, API calls and mobile-first responsive layout.
07. **testing skills.** A new `pytest` skill covers unit and API tests. The existing `playwright` skill is rewritten for end-to-end tests of a web app in a mobile viewport.
08. **removals.** The `webscraping` skill and all MCF-specific content are removed. The `deploy-and-validation-cycle` skill describes the easyMCF run loop, and its disposition is decided in task 05.03. Its RedBooks replacement is `redbooks-deploy-and-validation-cycle` in the later milestone.
09. **lessons inventory.** The **lessons inventory** lists every lesson from the easyMCF sources in the **source inventory**, with its source, its destination skill and file, or the reason it stays with easyMCF.
10. **lesson transfer.** Each transferred lesson is rewritten in RedBooks stack terms inside the destination skill, readable with the **easymcf repo** absent. Lessons about MCF scraping, the MCF site and AngularJS stay with easyMCF.
11. **staged loading.** Each skill keeps the rules that apply every time in its `SKILL.md`, and moves detailed lessons and worked examples to reference files in the skill folder. `SKILL.md` names each reference file and when to read it.
12. **settings.** The permission rules in the **project settings** that name easyMCF files, such as the MCF cookie export, are replaced with rules for RedBooks secrets and the personal financial data in `data/`.

Out of scope:

01. The bespoke `redbooks-` skills and the design decisions they record. They belong to the **agent skills implement customization** milestone.
02. Any design decision about the RedBooks data model, API, pages or stack versions. Generic skills state practice only.
03. Changes to the **easymcf repo**. It is a read-only source.
04. A project `CLAUDE.md`. The repo layout design topic decides whether RedBooks needs one. Project boundaries that easyMCF kept in its `CLAUDE.md` go into generic skills or into the lessons inventory as deferred to the design.
05. Application code, tests or scripts. This milestone writes only instruction files, the lessons inventory and this tracker.
06. Skill evaluation runs or trigger tuning with the skill-creator tooling.

**closure**

- **05.CK.01** every agent in `.claude/agents/` describes a RedBooks role and lists the generic skills it loads.
- **05.CK.02** every generic skill in scope items 02 to 07 exists in `.claude/skills/` and holds no RedBooks-specific names, paths or design decisions.
- **05.CK.03** every skill with RedBooks-specific content carries the `redbooks-` prefix.
- **05.CK.04** the `webscraping` skill and the MCF-specific content are removed from `.claude/`.
- **05.CK.05** a search of `.claude/` for easyMCF, MCF, Flask, SQLite and AngularJS returns no matches.
- **05.CK.06** the **lessons inventory** lists every lesson from the sources in the **source inventory**, with its destination skill and file, or a reason it stays with easyMCF.
- **05.CK.07** every transferred lesson is written in RedBooks stack terms and readable with the **easymcf repo** absent.
- **05.CK.08** every reference file in a skill folder is named in that skill's `SKILL.md`, with when to read it.
- **05.CK.09** every changed agent and skill file passes a **documentation-style** review.

Criteria 05.CK.01 to 05.CK.08 are the milestone closure criteria in the **release milestones**. 05.CK.09 is added by this tracker.
